# Changelog

All notable changes to Sprig are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versioning: [SemVer](https://semver.org/). Engine checkpoints are tagged `engine-0.x.y`
ahead of the 1.0 app; entry style from `engine-0.5.0` onward is 2–3 lines + the ADR

## [Unreleased]

### Changed
- **Plan vendored + planning docs realigned (M2.5 checkpoint)** — the master plan now lives in-repo (`docs/planning/master-plan.md`) after the original's loss; 53 stub ADRs re-pointed; ADR 0051 expanded in place; M2.5 checkpoint + re-scoped M3 in roadmap/milestones; slice gate codified (`docs/ci/slice-gate.md`); `VM-ENV-1` filed; R14 reframed/R16 added. Force-push stays in v1 behind the full high tier (master-plan §2.5/§10).

### Fixed
- **Hosted-Windows CI red since #145: credential-fixture isolation (quirk G2)** — git 2.54's Windows build no longer honors the `credential.helper=""` chain reset (empirically pinned vs git 2.43), so hosted runners' Git Credential Manager leaked test secrets across fixtures (one test even reached the real GitHub API with a stale token). Fixtures now isolate via `GIT_CONFIG_NOSYSTEM` + global-config redirection, with a `--show-origin` pin that the effective chain is exactly the local helper. No product change — `GitCredentialChainStore` deliberately honors the user's real chain.
- **House-style enforcement now covers the Recover vocabulary strings** — `notASnapshotRef`/`notABackupRef`/`recoveryRefMissing` were missing from the test catalog. Shared history-rewrite guards extracted to `GitCore.HistoryRewriteGuards` (behavior-neutral; ADR 0082/0083 engines now share one implementation).

## [engine-0.5.0] — 2026-06-11

The M2.5 portable-engine checkpoint (see `docs/planning/milestones.md`): the complete
task-window VM layer, IPC serving on two transports, the beginner-affordance backlog,
and the engine halves of M4–M6 — ADRs 0056–0083. Tagged on `main` as `engine-0.5.0`.

### Fixed
- **Intermittent full-suite hang (lost AsyncStream finish in `MockFileWatcher`)** — ~1-in-5 full `swift test` runs on the Linux snapshot toolchain hung forever in WatcherKit's "stream yields emitted events in order": `start(paths:)` attached its continuation via an unstructured Task, so a fast `stop()` could win the actor hop first — the nil-continuation `finish()` was lost and the late attach installed a continuation nobody would ever finish. Fixed with a finish-latch (attach replays pending events, then honors a raced-ahead finish); 500-iteration regression test. Cataloged as quirk **F3** with the diagnostic trap that cost us a mis-attribution first (`sigsuspend` + idle `ep_poll` does *not* prove tests finished — a parked async test occupies no thread). ci-linux.yml gains `timeout-minutes: 30` as a general anti-hang failsafe.

### Changed
- **Plain-register copy tightened; teaching parentheticals reduced to decision points (ADR 0072 amendment, maintainer-ratified 2026-06-11)** — all 29 `.plain` strings in `StatusVocabulary` reviewed and tightened ("you have 3 commit(s) not yet on origin/main (git: ahead by 3)" → "3 commit(s) to send to origin/main"). The `(git: …)` teaching device now appears on exactly five strings — the diverged relationship + diverged fast-forward report, both detached-HEAD lines, and the never-forces push rejection — enforced by a census test that counts parentheticals across every plain string, so a stray one can't creep back. The `.git` register (sprigctl's byte-pinned output) is untouched. VM inline failure/validation/cancellation strings ("Pick a branch to switch to first.", "No active midstream operation to finalize. Call refresh() first.") migrated into a single reviewed table, **`TaskWindowKit.TaskWindowVocabulary`**, with developer-speak rewritten in plain words ("No merge or rebase in progress to finalize — refresh first."); house style (trailing period, no flags, no parentheticals) is test-enforced. The table lives in TaskWindowKit because `Failure.description` is built inside the VMs and the dependency arrow points `UIKitShared → TaskWindowKit` (rationale in the ADR amendment).

### Added
- **Interactive-rebase engine: reorder / fold / drop over git's own sequencer (new ADR 0083, M5 substrate)** — `GitCore.RebasePlanOps` executes a `[RebaseStep]` plan via `git rebase -i`, injecting the todo through a one-shot `sequence.editor` whose command is a `printf` redirect — no shipped scripts, no embedded editor, and git keeps owning the entire state machine (conflict parking, `--continue`/`--abort`, reflog, hooks). Todo lines are strictly `verb + 40-hex SHA`, **validated before interpolation** — a malformed SHA (including shell metacharacters) is a typed `invalidPlan` refusal, pinned. Editor-free verb set v1: `pick`/`fixup`/`drop` + reordering (`squash`/`reword` open git's commit editor mid-run; they ride ADR 0082 and a later message-editing slice). Plans must cover each unpushed commit exactly once (drops explicit); fixup can't be first; the base is `HEAD~count` or `--root` when the range reaches the first commit. Safety = ADR 0082's contract plus the dirty-worktree refusal a replay needs. A conflicted replay parks git's rebase for the M4 resolver (typed path count; `rebase --abort` returns to the exact pre-plan tip, pinned); `TaskWindowKit.RebasePlanViewModel` mints the medium-tier snapshot at the pre-plan tip first, so a completed plan is one Recover restore away (round-trip pinned). 4 new vocabulary strings. 11 new tests (7 engine incl. conflict-park-abort + `--root` + injection guard, 4 VM incl. the round-trip).
- **`sprigctl clone` + `--browse` — the clone face, completing affordance 3.2's CLI story (ADR 0078 consequence closed)** — plain `sprigctl clone <url> [dir] [--depth N] [--no-submodules]` drives the same `CloneDialogViewModel` the task windows bind (CLI/shell parity); the default directory is the repository's name with `.git` stripped, like git's own. `--browse --provider <p>` composes the whole 3.2 chain: token from the ADR 0080 credential store (worded guidance naming both `sprigctl forge login` and the PAT path when not connected; a rejected token names re-login), repositories listed via `ForgeRepoBrowser`, numbered pick read from stdin, clone. 6 new tests against a local bare fixture (explicit + derived target, `--depth 1` single-commit history via the `file://` transport — local-path clones ignore depth, worded failure + exit 1, mutual-exclusion validation, deterministic not-connected guidance via a reset helper chain). The forge listing itself is the one path tests never touch (network).
- **History editing: reword last commit + squash last N (new ADR 0082, M5 head start)** — `GitCore.HistoryOps` under two hard contracts: **unpushed only** (a commit reachable from any remote-tracking ref refuses with the typed `refusedShared` — `branch -r --contains` is the oracle, checked on the OLDEST affected commit for squash, so the rewrite-then-force-push road is never offered) and **no silent content changes** (both verbs refuse when the index differs from HEAD — the classic `--amend` trap that folds staged work into the rewrite; reword's tree/parent/author and squash's tree are pinned byte-identical). Remaining guards: parked merge/rebase, detached/unborn HEAD, ranges that would swallow the root commit. New `reword`/`squash` op tags join the ADR 0033 medium tier; `TaskWindowKit.HistoryEditViewModel` mints the snapshot at the pre-edit HEAD before rewriting, so Recover's standard reset path is the one-click undo (squash → restore round-trip test-pinned). VM pre-guards (empty message, count bounds, nothing-unpushed via `unpushedCount`) are worded validation failures that spawn nothing and mint no snapshot. 7 new vocabulary strings. 15 new tests (8 engine vs a real bare origin, 5 VM incl. the round-trip, 2 tier rows).
- **Forge sign-in: OAuth device flow + `sprigctl forge login|logout|status` (new ADR 0081)** — `ForgeKit.ForgeDeviceFlow` implements RFC 8628 for GitHub (`github.com/login/device/code`) and GitLab (`{base}/oauth/authorize_device`; self-hosted bases supported): `begin` returns the user code + verification URI, `awaitToken` polls with the protocol's timing contract pinned **deterministically via an injected sleeper** — sleep `interval` before every poll, `slow_down` → +5 s, typed `.expired` once total sleep would exceed `expiresIn`, and mid-flow responses classified by body before status (GitLab sends `authorization_pending` as HTTP 400 per the RFC; GitHub as 200 — both normal flow, pinned). Client ids are **injected** like tokens (app registration is a distribution concern; self-hosted forges register their own). Bitbucket/Gitea have no reliable device grant — typed `unsupportedProvider`, worded as `sprigctl credential --set` PAT guidance. `forge login` stores the token under service `forge.<provider>` / account `token` — the same ADR 0080 key `sprigctl credential` uses, so the faces are interchangeable (test-pinned); a helperless chain yields configure-a-helper guidance, not a stack trace. With this, affordance 3.2 is end-to-end at the engine/CLI level: login → browse → clone. 13 new tests (8 engine incl. slow_down/budget/400-pending, 5 CLI), no network anywhere.
- **CredentialKit: secret storage that defers to git (new ADR 0080)** — `CredentialStore` protocol + `GitCredentialChainStore` portable default: secrets ride the user's `git credential` helper chain (`fill`/`approve`/`reject`), so the keystore that already holds their git credentials — osxkeychain, Git Credential Manager, libsecret — holds Sprig's forge tokens too, with zero new dependencies. Entries live under the synthetic `<service>.sprig.invalid` host (RFC 2606-reserved — can never shadow or clobber a real `github.com` credential; isolation test-pinned against a seeded real credential). `store()` verifies by read-back and throws `noUsableBackend` on a helperless chain — `git credential approve` exits 0 while silently storing nothing, and onboarding must never believe a token was kept when it wasn't. Newlines/NULs in any field are rejected before anything spawns (the wire format is line-based key=value — injection-proofed); prompting is disabled in depth (`GIT_TERMINAL_PROMPT=0` + stripped askpass hooks). CLI face: **`sprigctl credential --set|--get|--remove --service <s> --account <a>`** — `--set` reads the secret from stdin, never argv (`ps`-visible). Native keystore adapters remain the documented upgrade path behind the same protocol. Unblocks ADR 0078's `clone --browse` token source. 11 new tests (7 engine incl. isolation + helperless + injection + gnarly-secret round-trip, 4 CLI), all real git + the real store helper.
- **ForgeKit pagination + Bitbucket/Gitea providers (ADR 0078 follow-ups, closed)** — the browse list is no longer silently capped at 100 repos: every provider pages to an explicit `maxPages = 10` ceiling (~1000 most-recently-active repos), via the RFC 5988 `Link` header on GitHub/GitLab/Gitea (parser fails closed — no parseable `rel="next"` means "done", never a retry loop) and the body `next` URL on Bitbucket. The absolute next-URL is followed verbatim with auth preserved (pinned). **Bitbucket Cloud** joins (`/2.0/repositories?role=member&pagelen=100&sort=-updated_on`, bearer; `links.clone` array decode — a repo missing its `https` entry is a typed `malformedResponse`, not a silent skip) and so does **Gitea** (`/api/v1/user/repos?limit=50`, self-hosted `baseURL`, and the `Authorization: token <x>` scheme — Gitea's documented canonical form, NOT Bearer; test-pinned since it's the trap self-hosted users would hit). `ForgeProvider` is now the full v1 matrix: github, gitlab, bitbucket, gitea. Sources split (`ForgeHTTPClient` / browser core / per-provider wire code); shared multi-response test fake. 10 new tests.
- **Stash browser (new ADR 0079) — "where did my set-aside changes go?"** — `StashOps` gains the by-ref verbs a browser needs: `list()` (NUL-delimited `--format` parse into `StashEntry` — selector, commit SHA, date, subject), `apply(ref)` (never drops; conflicts are the typed `.conflicted` with the entry verifiably kept), `pop(ref)` (kept-on-conflict verified by **SHA survival in the stash reflog**, because selector indices shift), and `drop(ref)` (returns the SHA a safety copy points at). The new `TaskWindowKit.StashViewModel` re-resolves every verb's entry **by commit SHA against a fresh list** before acting — a list gone stale behind the VM's back (another window, the CLI, the auto-stash) can never misfire onto a neighbor entry; a vanished entry is a worded failure and the list self-corrects. The only drop verb is `dropKeepingSafetyCopy` (there is no "already safe" stash entry — ADR 0033 medium tier always applies): snapshot the stash commit under `refs/sprig/snapshots/…/stash-drop` first, then drop. **Recover restores stash-drop copies with `git stash store`** (additive; worktree and HEAD untouched) instead of `reset --hard` — both surfaces (`RecoverViewModel`, `sprigctl recover --restore`), with the drop → restore round-trip preserving SHA + subject exactly, pinned on both. 16 new tests (8 engine, 7 VM incl. the round-trip + stale-index misfire guard, 1 CLI).

- **UDS peer-credential validation (ADR 0076 follow-up, closed)** — `UnixSocketServer` gates every accepted connection on the peer's effective UID: `SO_PEERCRED` on Linux (locally-mirrored `ucred`; the Glibc overlay hides the real one), `getpeereid` on Darwin. Pinned by a genuinely **two-process end-to-end test**: the agent process serving, the test process as the UDS client — connect → `subscribe` → `subscribeAck` → file change → `badgeChanged` envelope, over the same framed wire format the Windows named pipe uses. 3 new tests (the e2e + 2 tee-sink units).

### Fixed
- **Linux CI SIGSEGV in `Process.run()` fixed via toolchain pin** — the suite-wide crash that exhausted all 3 Linux CI retries on `main` ("Bad pointer dereference", crash frame `__memmove_avx_unaligned_erms` ← `Process.run()`) is upstream swift-corelibs-foundation [#5472](https://github.com/swiftlang/swift-corelibs-foundation/issues/5472): `findMaximumOpenFromProcSelfFD()` memcpy's a fixed 256 bytes of each `/proc/self/fd` dirent's `d_name`, over-reading short records and faulting when the final record lands near an unmapped page. The upstream fix (`81eb85a`, merged 2026-05-19) is in no stable release yet — 6.3.2 predates it and `release/6.4.x` branched 6 commits before it — so Linux is pinned to `main-snapshot-2026-05-27` (`.swift-version` for swiftly-managed local dev, matching `swiftlang/swift` nightly digest for the ci-linux.yml container). A code-level workaround (serializing all `process.run()` launches behind a global lock) was implemented first and **empirically disproven** — the crash reproduced inside the serialized window — so it was reverted rather than shipped as a placebo. Re-pin to a stable release is tracked in `docs/planning/audit-followups.md` (`UP-5472`). macOS (Darwin Foundation) and Windows (no `/proc` scan) are unaffected.
- **`GitMetadataPaths.resolveGitDir` forward-compat with swift-foundation** — surfaced by the snapshot pin above: swift-foundation both stops resolving `.path` against `baseURL` *and* applies strict RFC 3986 relative resolution (stripping the base's last component when it lacks a trailing slash), so relative `gitdir:` pointers (submodule shape, `gitdir: ../.git/modules/<name>`) resolved one directory too high and threw `gitdirPointerTargetMissing`. Fixed by replacing `URL(fileURLWithPath:relativeTo:)` with explicit component-wise `appendPathComponent` + `.standardized`, which is contract-stable on both Foundation implementations. This was the only `relativeTo:` call site in the codebase; the hazard is now cataloged as quirk **D3** in `docs/architecture/cross-platform-quirks.md`.

### Added
- **`TransportKit.NamedPipeServer`** — multi-client accept loop on top of the OVERLAPPED `NamedPipeTransport` primitive. The Windows-Service-hosted agent constructs one `NamedPipeServer(pipeName:)` and consumes `connections` (an `AsyncStream<NamedPipeTransport>`); each yielded transport is one shell-extension or `sprigctl` client. `close()` is cancel-deterministic — signals the cancel event, finishes the stream, awaits the GCD accept-thread exit off the cooperative pool. Closes the "multi-client accept loop with `PIPE_UNLIMITED_INSTANCES`" item that the OVERLAPPED single-client MVP explicitly deferred (ADR 0067).
  - **One reusable accept-complete event** across iterations (manual-reset, `ResetEvent` before each `ConnectNamedPipe` inside `NamedPipeIO.acceptClient(...)`); one cancel event signaled by `close()`; one exit event the accept thread sets on its way out so `close()` can await deterministic teardown.
  - **Independent per-client lifecycle.** `server.close()` does NOT close the transports it has already yielded — the consumer of `connections` owns each accepted `NamedPipeTransport` and decides when to close it. Verified by the `serverCloseDoesNotCloseAcceptedTransports` test (a round-trip still works through the per-client transport after the server is closed).
  - **Still deferred (per ADR 0067):** `CreateThreadpoolIo`-based fan-out (closes the small "next instance not yet created" window between accepts), per-user-SID DACL, and client reconnect on broken pipe. All three are pure additive layers on top of `NamedPipeServer`; the public API is shaped to absorb them without churn.

- **`TransportKit.NamedPipeTransport`** — first real Windows IPC transport, replacing the previous `fatalError` stub. The single-client primitive the M2-Win shell-extension + Windows-service host build on (per `docs/research/windows-shell-apis.md`'s "Named-pipe IPC: the server side"). Tier 2 platform impl; the Tier 1 `Transport` protocol stays single-impl across all OSes.
  - **Server side**: `NamedPipeTransport.server(pipeName:)` creates the pipe via `CreateNamedPipeW` and awaits one client via `ConnectNamedPipe`. **Client side**: `NamedPipeTransport.client(pipeName:)` opens an existing pipe via `CreateFileW`. **Test helper**: `connectedPair(pipeName:)` wires both ends inside a single process for unit testing.
  - **Wire format**: 4-byte little-endian length prefix + payload bytes, matching the framing every other Sprig transport uses so `IPCSchema.EnvelopeCodec` stays single-impl across XPC (macOS) and D-Bus/UNIX-socket (Linux). Hard cap at `maxFrameSize` (16 MB) for memory safety against misbehaving peers.
  - **Concurrency**: blocking `ReadFile` / `ConnectNamedPipe` run on `DispatchQueue.global(qos: .userInitiated)`, NOT Swift's cooperative pool — a few transports' worth of pinned reads would otherwise starve every async task in the process. Sends serialize through `Synchronization.Mutex<Void>` (the Windows toolchain marks `NSLock.lock`/`unlock` unavailable from async contexts).
  - **Close semantics**: `close()` runs `CancelIoEx` (wakes the local read loop) + `CloseHandle` (propagates `ERROR_BROKEN_PIPE` to the peer's next read) + finishes the inbound `AsyncStream`. `deinit` is best-effort cleanup gated on the close-state flag so double-`CloseHandle` (undefined behavior on Windows) is impossible.
  - **Deliberately deferred** to follow-up M2-Win slices: multi-client accept loop with `PIPE_UNLIMITED_INSTANCES`, per-user-SID DACL, client reconnect on broken pipe, and the OVERLAPPED-I/O + `CreateThreadpoolIo` (IOCP) variant that lifts the single-client cap. The production agent uses one `NamedPipeTransport` per connection for its lifetime; the missing pieces are server-orchestration concerns.

Tracked in `docs/planning/disabled-tests.md`; re-enabled when the IOCP refactor lands. The byte-level `Transport` contract is also covered cross-platform by `InProcessTransportTests`.

  - New `DiffPayload` value type carries the raw unified-diff bytes plus a `filesChanged: Int` count derived from `diff --git ` headers. Structured per-file / per-hunk parsing is deliberately deferred (likely a future `DiffKit`) until M4 MergeConflictResolver tells us what shape it needs.
  - Actor-isolated `DiffViewerViewModel` exposes `target`, `payload`, and `state: TaskWindowState<Int>` (success payload = file count). `setTarget(_:)` swaps the target without auto-reloading and **preserves the prior payload** during the refetch so the UI doesn't blank mid-load. `cancel()` interrupts an in-flight load while leaving the prior payload intact; `reset()` returns state to `.idle` while preserving both payload and target.
  - `countDiffGitHeaders(in:)` is a bytewise scanner that only counts markers at start-of-input or after a newline — so a commit message that happens to mention "diff --git" in passing doesn't inflate the file count. Internal-visible for tests; covered by a pure-function test.
- **LogBrowserViewModel** — third concrete M3 view model, the portable engine behind the macOS/Windows "Show Log…" task window:
  - Actor-isolated VM exposing `revSpec` (default `HEAD`; accepts anything `git log` does), `pageSize` (default 50), `commits: [Commit]` (the accumulating page cache), `hasMore: Bool`, and `state: TaskWindowState<Int>` where the success payload is the total commits loaded across all pages so far.
  - `loadInitial()` discards the cache and loads the first page; `loadMore()` appends the next page via `--skip` + `--max-count`. `hasMore` flips to `false` automatically when git returns a short page (history exhausted).
  - `setRevSpec(_:)` and `setPageSize(_:)` configure the next load **without** auto-reloading — the UI resets scroll / selection on its own terms. `cancel()` interrupts in-flight loads; `reset()` returns to `.idle` while preserving cached commits so the user doesn't lose data on a dismissed error banner.
  - Establishes the "paginate a list" pattern that M5 RebaseInteractive's reflog view and a future BlameViewer's per-line view will reuse.
- **BranchSwitcherViewModel + GitCore.BranchListing parser** — second concrete M3 view model, the portable engine behind the macOS/Windows "Switch Branch…" task window:
  - New `GitCore.BranchListing` parser: pure-data type that consumes `git for-each-ref refs/heads/ --format=…` output and produces an ordered `[Branch]`. Each `Branch` carries `shortName`, `fullName`, `sha`, and `isHead`. Mirrors `LogParser`'s pattern (parser-only struct; callers spawn git via `Runner`). Uses **TAB-separated, newline-terminated** entries because `git for-each-ref` only learned the `%xNN` byte-literal format atom in git 2.46, and the project floor is git 2.39 (ADR 0047); `git check-ref-format` forbids tabs and newlines in refnames so the split is unambiguous on every supported git version.
  - New `TaskWindowKit.BranchSwitcherViewModel`: actor-isolated VM exposing `inventory: [Branch]`, `selection: String?`, and `state: TaskWindowState<String>`. `refresh()` populates the inventory and marks HEAD; `select(_:)` accepts only known names (no-ops on unknown — keeps the selection well-formed for the UI); `switchBranch()` runs `git switch <name>`, surfaces real `GitError` failures (e.g. dirty-tree blocks), and soft no-ops to `.success` when the user picks the branch HEAD already points at. `reset()` returns to `.idle` while preserving inventory + selection so the "switch again without re-refreshing" UX is one click. Cancellation lands in `.failure("Switch cancelled.")` per the VM-pattern convention.
- **TaskWindowKit foundation + first VM** — the portable view-model layer every M3 task window will build on, plus its first concrete user: a fully-functional `CloneDialogViewModel`.
  - `TaskWindowState<Success>` — the shared lifecycle enum (`idle` / `busy(progress:)` / `success` / `failure`). `Sendable` + `Equatable` across actor boundaries. Carries a `Failure` companion (description + optional `underlyingTypeName`) so diagnostics tooling can group failures without `any Error` needing to ride the wire. Convenience accessors: `isBusy`, `isTerminal`, `successValue`, `failure`.
  - `CloneRequest` — value-type form inputs for the Clone task window (source URL, target directory, recurseSubmodules default-on per master plan §10, optional shallow depth). Self-validating via `validationError` / `isReady`; `gitArguments()` builds the exact argv `git clone` is invoked with.
  - `CloneDialogViewModel` — actor-isolated view model that owns the request, runs `git clone` via injected `GitCore.Runner`, and surfaces results via `TaskWindowState<URL>`. Pre-flights validation (invalid form lands in `.failure` without spawning git), supports `cancel()` and `reset()` for "abort" and "do over" UX, and returns the cloned worktree's absolute URL in the success branch so callers can hand it to `RepoState` discovery or open it in Finder/Explorer.
  - First M3 view model — establishes the pattern for the remaining five (CommitComposer, LogBrowser, DiffViewer, BranchSwitcher, Preferences). Each subsequent VM lands in its own PR using these primitives.
- **IPCSchema v1 wire-format locked down** — the on-the-wire JSON envelope between `SprigAgent` and every consumer (FinderSync extension, Windows shell extension, `sprigctl`, task-window app) is now contractually frozen for the v1 schema version:
  - `packages/IPCSchema/STABILITY.md` — the wire-format policy. Names what's stable (envelope key set, every `kind` discriminator, every payload field name, sorted-key JSON output, ISO-8601 dates, `IPCError` cases) vs. what's safely extensible (new `EnvelopeMessage` cases, new optional payload fields, new wire-stable string-enum values). New variants must come with both encode-direction and decode-direction golden tests in the same PR.
  - `packages/IPCSchema/Tests/IPCSchemaTests/WireFormatGoldenTests.swift` — single source of truth for the v1 wire-format contract. Encode-golden (typed value → exact bytes) and decode-golden (exact bytes → typed value) for every variant of every `EnvelopeMessage` enum (`ClientRequest.{badgeQuery, subscribe}`, `AgentResponse.{badgeReply, subscribeAck, error}`, `AgentEvent.{badgeChanged, subscriptionEnded}`). The two-directional coverage catches silent wire drift in either direction, which round-trip-only tests miss when encoder + decoder co-evolve a breaking change in lockstep.
  - The pre-existing single-variant `wireShapeRegression()` tests in `EnvelopeTests.swift` + `AgentEventTests.swift` were superseded by the consolidated file and removed; their content lives in the new file alongside the previously-missing five variants' goldens.
- **SafetyKit complete pre-V1** — closes the destructive-op safety surface for ADR 0033:
  - `SnapshotWriter.withSnapshot(op:target:_:)` async helper. Creates a `refs/sprig/snapshots/<ts>/<op>` ref, runs the supplied body, returns the body's value. If body throws, the helper rethrows but the snapshot ref **persists** in git refs so the user can recover via `git update-ref HEAD <snapshot.refName>` (or, once it ships, the Recover task window / `sprigctl recover`).
  - `DestructiveOpTier` enum (`.low` / `.medium` / `.high`) plus `UndoBannerPolicy` companion — the three-tier confirmation classification from ADR 0033. Accessors: `requiresSnapshot`, `requiresTypedPhrase`, `undoBannerPolicy`. `tier(for: String)` lookup is **fail-closed** — unknown op-tags return nil rather than defaulting to `.low`, so adding a new destructive op forces an explicit tier decision.
  - Call sites (`MergeConflictResolver`, `RebaseInteractive`, `ForcePushDialog`, etc.) wire through `withSnapshot` + `DestructiveOpTier.tier(for:)` as those features build out; this PR ships the primitive, not the orchestration.

- `sprigctl agent` subcommand (`sprigctl agent <repo> [--polling] [--polling-interval SECS] [--duration SECS] [--stats-interval SECS]`): runs the cross-platform `RepoAgent` host against a single repo and streams `Envelope<AgentEvent>` envelopes as JSON-per-line on stdout. - **AgentKit public surface** (consumed by `sprigctl agent` and the in-flight M2-Mac LaunchAgent host):
  - `RepoAgent` — long-lived per-repo host wiring watcher → refresh driver → status refresher → badge store → broadcaster → registry → sink. Exposes `refreshAttempts() / lastOutcome() / firstDeferralAt()` diagnostics.
  - `InMemoryBadgeEventSink` — `AsyncStream<Envelope<AgentEvent>>` sink for in-process consumption (CLI, tests).
  - `TransportBadgeEventSink` — wire-bound sink that JSON-encodes envelopes via `IPCSchema.EnvelopeCodec` and forwards to a `TransportKit.Transport`. Single-client hosts use this directly.
  - `RoutedBadgeEventSink` + `SubscriptionTransportRoutes` — multi-client variant: per-subscription routing so a host serving N concurrent clients delivers each event only to the transport that owns its subscription. Includes `unregisterAll(transport:)` for connection-disconnect cleanup.
  - `ClientRequestDispatcher` — inbound IPC half. Drains `Transport.messages()`, decodes `Envelope<ClientRequest>` (`subscribe` / `badgeQuery`), dispatches to the registry, writes correlated `Envelope<AgentResponse>` replies. Wire-stable error codes for unknown / malformed envelopes.
