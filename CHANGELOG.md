## [Unreleased]

### Added
- **MergeConflictResolverViewModel — M4 MVP-gate VM** — the portable engine behind the macOS/Windows "Resolve Conflicts…" task window. Wires `UnmergedListing` + `ConflictKind` (the prereq landing alongside) into an actor that walks the user through resolving every conflicted path and finalizing the merge.
  - New `ConflictKit.ConflictedPathChoice` enum (`pending` / `ours` / `theirs` / `base`) — whole-side picks that work for every `ConflictKind`. `stage` accessor maps each choice to its `UnmergedStage` number (1 = base, 2 = ours, 3 = theirs); `isResolved` is the convenience inverse of `.pending`.
  - Actor-isolated `MergeConflictResolverViewModel` exposes `conflicts: [ClassifiedConflict]`, `choices: [String: ConflictedPathChoice]`, `resolvedPaths: Set<String>`, and `state: TaskWindowState<Int>` (success payload = remaining unresolved count). Operations: `refresh()` re-reads + reclassifies the inventory (dropping stale choices for paths that left the conflict set); `choose(path:_:)` sets a choice (silently no-ops on unknown paths); `clearChoice(for:)` undoes both choice and resolved-set entry; `applyOne(path:)` / `applyAll()` write each chosen stage's blob to disk via `CatFileBatch` + `git add` (substituting `git update-index --cacheinfo` for submodule stages whose "blob" is actually a commit SHA); `finalize()` runs `git commit --no-edit` (auto-uses `.git/MERGE_MSG`); `abort()` runs `git merge --abort` and clears in-memory state.
  - New `MergeApplyError` typed enum (`pending(path:)` / `missingStage(path:stage:)`) — diagnostics-grade categorization for the apply pipeline. Wrapped into `TaskWindowState.failure` on the external surface.
  - Pre-flight rejections (no git spawned): `applyOne` with a `pending` choice → "Pick a side for '<path>' first."; `applyAll` with no resolutions → "No paths have a resolution to apply."; `finalize` with unresolved paths → "N path(s) still unresolved."
  - **Deliberately deferred** to follow-ups (file header documents): per-region text resolution (uses `ConflictedFile.applying(_:)` once diff-rendering selection UX is wired); rebase / cherry-pick / am finalization branches; LFS pointer auto-fetch after a pick; AI-suggested resolutions (ADR 0028 gates on M7).
  - `Package.swift` — TaskWindowKit gains a `ConflictKit` dep (documented inline). Tier-1 → Tier-1 so no platform coupling.
- **ConflictKit non-text conflict classification** — M4 MergeConflictResolver prereq. Adds the missing pieces that distinguish line-mergeable text conflicts from the variants that need different UX affordances (binary / LFS pointer / submodule / add-add).
  - New `GitCore.UnmergedListing` parser — pure-data consumer of `git ls-files -u -z` output. Produces `[UnmergedEntry]`, each carrying the path plus 1–3 `UnmergedStage` entries (stage 1 = base/ancestor, 2 = ours, 3 = theirs). Convenience accessors on the entry: `baseStage` / `oursStage` / `theirsStage`, `isAddAdd` (true when stage 1 is absent), `hasSubmoduleStage` (true when any stage's mode is 160000). Mirrors the `LogParser` / `BranchListing` / `PorcelainV2Parser` parser-only-struct pattern.
  - New `GitCore.GitFileMode` typed enum — `regularFile` (100644), `executable` (100755), `symlink` (120000), `submodule` (160000), `unknown(UInt32)` for anything else. Round-trips via `rawMode`.
  - New `ConflictKit.ConflictKind` enum — five cases (`text` / `binary` / `lfsPointer` / `submodule` / `addAdd`) drive the M4 MergeConflictResolver's per-path UI affordance. `ConflictKind.classify(_:probes:)` is a pure function over an `UnmergedEntry` plus an optional `ConflictProbes` (caller-supplied `isLFSTracked` / `isBinary` closures — the parser can't infer those from `ls-files` alone). Classification rules in priority order: submodule mode → LFS-tracked (wins over binary because the UX is more specific) → binary → addAdd → default text.
  - New `ConflictKit.ClassifiedConflict` value type pairs an `UnmergedEntry` with its `ConflictKind`. `ConflictKind.classifyAll(_:probes:)` is the bulk-classify convenience for the typical "feed the whole `UnmergedListing.parse` output through" flow.
  - ConflictKit gains a `GitCore` package dependency (wired in `Package.swift`). The marker-parser side of ConflictKit (`ConflictParser`, `ConflictedFile`, `ConflictRegion`) stays pure-Foundation; the dep is only needed for the new typed-classifier surface.
- **DiffViewerViewModel** — fourth concrete M3 view model, the portable engine behind the macOS/Windows "Diff…" task window:
  - New `DiffTarget` enum (`worktreeAgainstIndex` / `indexAgainstHead` / `commit(sha:)`) captures the three diff modes M3 needs at MVP. Each maps to one canonical git invocation; adding new cases (arbitrary `<rev>..<rev>` ranges, file-scoped diffs, `--remerge-diff`) is one switch entry plus a test.
  - New `DiffPayload` value type carries the raw unified-diff bytes plus a `filesChanged: Int` count derived from `diff --git ` headers. Structured per-file / per-hunk parsing is deliberately deferred (likely a future `DiffKit`) until M4 MergeConflictResolver tells us what shape it needs.
  - Actor-isolated `DiffViewerViewModel` exposes `target`, `payload`, and `state: TaskWindowState<Int>` (success payload = file count). `setTarget(_:)` swaps the target without auto-reloading and **preserves the prior payload** during the refetch so the UI doesn't blank mid-load. `cancel()` interrupts an in-flight load while leaving the prior payload intact; `reset()` returns state to `.idle` while preserving both payload and target.
  - `countDiffGitHeaders(in:)` is a bytewise scanner that only counts markers at start-of-input or after a newline — so a commit message that happens to mention "diff --git" in passing doesn't inflate the file count. Internal-visible for tests; covered by a pure-function test.
- **LogBrowserViewModel** — third concrete M3 view model, the portable engine behind the macOS/Windows "Show Log…" task window:
  - Actor-isolated VM exposing `revSpec` (default `HEAD`; accepts anything `git log` does), `pageSize` (default 50), `commits: [Commit]` (the accumulating page cache), `hasMore: Bool`, and `state: TaskWindowState<Int>` where the success payload is the total commits loaded across all pages so far.
  - `loadInitial()` discards the cache and loads the first page; `loadMore()` appends the next page via `--skip` + `--max-count`. `hasMore` flips to `false` automatically when git returns a short page (history exhausted).
  - `setRevSpec(_:)` and `setPageSize(_:)` configure the next load **without** auto-reloading — the UI resets scroll / selection on its own terms. `cancel()` interrupts in-flight loads; `reset()` returns to `.idle` while preserving cached commits so the user doesn't lose data on a dismissed error banner.
  - Establishes the "paginate a list" pattern that M5 RebaseInteractive's reflog view and a future BlameViewer's per-line view will reuse.
- **BranchSwitcherViewModel + GitCore.BranchListing parser** — second concrete M3 view model, the portable engine behind the macOS/Windows "Switch Branch…" task window:
  - New `GitCore.BranchListing` parser: pure-data type that consumes `git for-each-ref refs/heads/ --format=…` output and produces an ordered `[Branch]`. Each `Branch` carries `shortName`, `fullName`, `sha`, and `isHead`. Mirrors `LogParser`'s pattern (parser-only struct; callers spawn git via `Runner`). Uses **TAB-separated, newline-terminated** entries because `git for-each-ref` only learned the `%xNN` byte-literal format atom in git 2.46, and the project floor is git 2.39 (ADR 0047); `git check-ref-format` forbids tabs and newlines in refnames so the split is unambiguous on every supported git version.
  - New `TaskWindowKit.BranchSwitcherViewModel`: actor-isolated VM exposing `inventory: [Branch]`, `selection: String?`, and `state: TaskWindowState<String>`. `refresh()` populates the inventory and marks HEAD; `select(_:)` accepts only known names (no-ops on unknown — keeps the selection well-formed for the UI); `switchBranch()` runs `git switch <name>`, surfaces real `GitError` failures (e.g. dirty-tree blocks), and soft no-ops to `.success` when the user picks the branch HEAD already points at. `reset()` returns to `.idle` while preserving inventory + selection so the "switch again without re-refreshing" UX is one click. Cancellation lands in `.failure("Switch cancelled.")` per the VM-pattern convention.
- **TaskWindowKit foundation + first VM** — the portable view-model layer every M3 task window will build on, plus its first concrete user: a fully-functional `CloneDialogViewModel`.
  - `TaskWindowState<Success>` — the shared lifecycle enum (`idle` / `busy(progress:)` / `success` / `failure`). `Sendable` + `Equatable` across actor boundaries. Carries a `Failure` companion (description + optional `underlyingTypeName`) so diagnostics tooling can group failures without `any Error` needing to ride the wire. Convenience accessors: `isBusy`, `isTerminal`, `successValue`, `failure`.
  - `CloneRequest` — value-type form inputs for the Clone task window (source URL, target directory, recurseSubmodules default-on per master plan §10, optional shallow depth). Self-validating via `validationError` / `isReady`; `gitArguments()` builds the exact argv `git clone` is invoked with.
  - `CloneDialogViewModel` — actor-isolated view model that owns the request, runs `git clone` via injected `GitCore.Runner`, and surfaces results via `TaskWindowState<URL>`. Pre-flights validation (invalid form lands in `.failure` without spawning git), supports `cancel()` and `reset()` for "abort" and "do over" UX, and returns the cloned worktree's absolute URL in the success branch so callers can hand it to `RepoState` discovery or open it in Finder/Explorer.
  - First M3 view model — establishes the pattern for the remaining five (CommitComposer, LogBrowser, DiffViewer, BranchSwitcher, Preferences). Each subsequent VM lands in its own PR using these primitives.
- **IPCSchema v1 wire-format locked down** — the on-the-wire JSON envelope between `SprigAgent` and every consumer (FinderSync extension, Windows shell extension, `sprigctl`, task-window app) is now contractually frozen for the v1 schema version:
  - `packages/IPCSchema/STABILITY.md` — the wire-format policy. Names what's stable (envelope key set, every `kind` discriminator, every payload field name, sorted-key JSON output, ISO-8601 dates, `IPCError` cases) vs. what's safely extensible (new `EnvelopeMessage` cases, new optional payload fields, new wire-stable string-enum values). New variants must come with both encode-direction and decode-direction golden tests in the same PR.
  - `packages/IPCSchema/Tests/IPCSchemaTests/WireFormatGoldenTests.swift` — single source of truth for the v1 wire-format contract. Encode-golden (typed value → exact bytes) and decode-golden (exact bytes → typed value) for every variant of every `EnvelopeMessage` enum (`ClientRequest.{badgeQuery, subscribe}`, `AgentResponse.{badgeReply, subscribeAck, error}`, `AgentEvent.{badgeChanged, subscriptionEnded}`). The two-directional coverage catches silent wire drift in either direction, which round-trip-only tests miss when encoder + decoder co-evolve a breaking change in lockstep.
  - The pre-existing single-variant `wireShapeRegression()` tests in `EnvelopeTests.swift` + `AgentEventTests.swift` were superseded by the consolidated file and removed; their content lives in the new file alongside the previously-missing five variants' goldens.
- **SafetyKit complete pre-V1** — closes the destructive-op safety surface for ADR 0033:
  - `SnapshotWriter.withSnapshot(op:target:_:)` async helper. Creates a `refs/sprig/snapshots/<ts>/<op>` ref, runs the supplied body, returns the body's value. If body throws, the helper rethrows but the snapshot ref **persists** in git refs so the user can recover via `git update-ref HEAD <snapshot.refName>` (or, once it ships, the Recover task window / `sprigctl recover`).
  - `DestructiveOpTier` enum (`.low` / `.medium` / `.high`) plus `UndoBannerPolicy` companion — the three-tier confirmation classification from ADR 0033. Accessors: `requiresSnapshot`, `requiresTypedPhrase`, `undoBannerPolicy`. `tier(for: String)` lookup is **fail-closed** — unknown op-tags return nil rather than defaulting to `.low`, so adding a new destructive op forces an explicit tier decision.
  - Call sites (`MergeConflictResolver`, `RebaseInteractive`, `ForcePushDialog`, etc.) wire through `withSnapshot` + `DestructiveOpTier.tier(for:)` as those features build out; this PR ships the primitive, not the orchestration.
- **M1 → M2 exit gate — two of three criteria** now enforced on every PR across macOS / Linux / Windows via the new `tests/integration/` target; the third (100k-file budget) stays formally deferred to self-hosted hardware but has its infrastructure wired (benchmark ladder + opt-in smoke):
  - `SprigctlStatusByteMatchTests` — `PorcelainV2Parser.parse(_:)` correctness across the documented fixture states (clean / modified / staged / both / untracked / deleted / renamed / gitignored / merge-conflict). Closes M1's parser-fidelity exit criterion. Interpretation note in `docs/planning/milestones.md`: sprigctl status itself emits human-readable / JSON output, so the literal "byte equality of binary outputs" wording was impossible by design; the honest test is parser correctness, which this PR enforces.
  - `WatcherEventBudgetTests` — `EventCoalescer` ingests + drains 10k synthetic `WatchEvent` values within a single-core wall-clock budget (1 s ceiling vs. typical ~30 ms locally). Closes M1's watcher-CPU exit criterion as a wall-clock proxy (CPU % isn't portably readable from inside swift-testing).
  - `Status100kFileBudgetTests` — synthesizes a 100 000-file repo via `FixtureSynthesizer.makeRepoWithFileCount(_:)`, runs `git status --porcelain=v2 -z` + `PorcelainV2Parser.parse(_:)` against it, asserts the measured window completes inside a 60 s wall-clock ceiling. **Opt-in via `SPRIG_RUN_SCALE_TESTS=1`** — disabled on default `swift test` and every hosted-CI workflow because 100 k file synthesis dominates per-job time on hosted runners (potentially several minutes on Windows per the cross-platform-quirks catalog) without commensurate signal beyond what the smaller-fixture parser-fidelity suite already gives. Available for manual spot checks (e.g. before a release tag) and for a future self-hosted nightly workflow. The fine-grained perf comparisons (sustained CPU%, peak RSS, latency distributions per ADR 0021) still need stable hardware; the existing `Benchmarks/SprigCoreBenchmarks.swift` ladder is **extended to 100k** here so those measurements run automatically when the self-hosted runner comes online (see `docs/ci/self-hosted.md`).
  - New shared `IntegrationSupport` library hosts `FixtureSynthesizer` (clean / modified / staged / staged-and-modified / untracked / deleted / merge-conflict / renamed / gitignored repo synthesizers backed by real `git init` + `git commit`, plus `makeRepoWithFileCount(_:dirtyFraction:_:)` for scale tests). Available for the benchmark target to consume in a follow-up PR, replacing the inline synthesizers in `Benchmarks/SprigCoreBenchmarks.swift`.
- Initial project scaffolding: three-tier package structure, ADRs 0001–0053, CI matrix (macOS 14/15 + Linux Swift 6.3 + Windows Swift 6.3), SwiftLint rules enforcing cross-platform discipline.
- `sprigctl agent` subcommand (`sprigctl agent <repo> [--polling] [--polling-interval SECS] [--duration SECS] [--stats-interval SECS]`): runs the cross-platform `RepoAgent` host against a single repo and streams `Envelope<AgentEvent>` envelopes as JSON-per-line on stdout. Useful for ad-hoc debugging of the badge-update flow without a FinderSync extension. `--stats-interval` adds periodic `# stats: {…}` JSON lines on stderr summarizing the agent's `refreshes`, `outcome`, `entryCount`, and `firstDeferralAt` (the ADR 0066 stale-`index.lock` enabler).
- **AgentKit public surface** (consumed by `sprigctl agent` and the in-flight M2-Mac LaunchAgent host):
  - `RepoAgent` — long-lived per-repo host wiring watcher → refresh driver → status refresher → badge store → broadcaster → registry → sink. Exposes `refreshAttempts() / lastOutcome() / firstDeferralAt()` diagnostics.
  - `InMemoryBadgeEventSink` — `AsyncStream<Envelope<AgentEvent>>` sink for in-process consumption (CLI, tests).
  - `TransportBadgeEventSink` — wire-bound sink that JSON-encodes envelopes via `IPCSchema.EnvelopeCodec` and forwards to a `TransportKit.Transport`. Single-client hosts use this directly.
  - `RoutedBadgeEventSink` + `SubscriptionTransportRoutes` — multi-client variant: per-subscription routing so a host serving N concurrent clients delivers each event only to the transport that owns its subscription. Includes `unregisterAll(transport:)` for connection-disconnect cleanup.
  - `ClientRequestDispatcher` — inbound IPC half. Drains `Transport.messages()`, decodes `Envelope<ClientRequest>` (`subscribe` / `badgeQuery`), dispatches to the registry, writes correlated `Envelope<AgentResponse>` replies. Wire-stable error codes for unknown / malformed envelopes.
- `docs/architecture/agent-host.md` — composition reference for both single-client and multi-client agent host wiring; the M2-Mac LaunchAgent picks up this pattern with XPC swapped in for `InProcessTransport`.
